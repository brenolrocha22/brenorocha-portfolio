## Problema

Um RAG "ingênuo" sobre uma tabela de vendas devolve só algumas linhas parecidas com a pergunta e não calcula totais. Quando alguém pergunta "quanto foi vendido?", o modelo tende a inventar o número.

## Solução

Um agente com **duas ferramentas**, cada uma para um tipo de pergunta:

- `consultar_sql`: consulta um banco SQLite aberto em **modo somente leitura**, que aceita apenas `SELECT` e `WITH`. Totais, médias e contagens saem do SQL, não do modelo.
- `buscar_documentos`: busca semântica (RAG) no ChromaDB, para vendas específicas e para 119 resumos pré-calculados.

O LLM escolhe a ferramenta e redige a resposta com as fontes, mas **não faz contas**.

## Arquitetura

1. A planilha original (XLSX), com vendas reais, passa por `export_data.py`, que anonimiza os nomes dos clientes e gera 3 CSVs: vendas, veículos e clientes.
2. Os CSVs viram documentos de contexto indexados com LlamaIndex no ChromaDB, com embeddings locais (FastEmbed).
3. Os mesmos CSVs alimentam o banco SQLite somente leitura.
4. A interface em Chainlit envia a pergunta ao agente, que usa o Llama 3.1 8B via OpenRouter e responde com as fontes usadas.

O projeto roda com Docker e Docker Compose. Um relatório Power BI em formato PBIP (modelo TMDL e relatório PBIR, versionáveis no Git) usa a mesma base e mostra os mesmos totais: 985 vendas e faturamento de 59.835.220,02.

## Resultados

- Números rastreáveis: cada total vem de uma consulta SQL que pode ser conferida.
- 19 testes automatizados conferem o comportamento crítico, entre eles: o total de faturamento bate com o CSV (`test_total_revenue_matches_csv`), a conexão é somente leitura (`test_connection_is_read_only`) e comandos diferentes de `SELECT` são rejeitados (`test_rejects_statements_other_than_select`).
- A anonimização dos clientes também é coberta por teste.

## Limitações

- Não há demo online: o chatbot precisa de uma chave da OpenRouter para rodar.
- Ainda não há integração contínua (CI) executando os testes.
- O README é longo e concentra muita informação em um só arquivo.
